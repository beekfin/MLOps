# Разбор дефектов

## 1. Данные попадали в Git

**Проблема.** Каталог `data/` не был указан в `.gitignore`, DVC remote не был
настроен, а `val.jsonl` и `test.jsonl` не были объявлены как выходы DVC.

**Как проявлялось.** После `git add .` JSONL-файлы могли попасть в историю Git,
а часть результатов разбиения вообще не версионировалась через DVC.

**Исправление.** `data/` добавлен в `.gitignore`, настроен локальный DVC remote,
а `raw`, `clean`, `train`, `val` и `test` объявлены в `outs` соответствующих
стадий. Снимок источника также хранится в DVC через
`source/askubuntu.jsonl.dvc`.

**Проверка числом.** `git ls-files data/` возвращает 0 файлов; самопроверка
находит 5 из 5 путей данных в DVC outputs и один настроенный remote.

## 2. Смена версии не пересчитывала пайплайн

**Проблема.** Стадия `collect` не зависела от файла источника и параметров,
которые определяют версию выборки. DVC мог считать старый результат актуальным.

**Как проявлялось.** После переключения `collect.version` команда `dvc repro`
не изменяла `clean.jsonl`.

**Исправление.** В зависимости `collect` добавлен
`source/askubuntu.jsonl`, а в `params` — секции `collect`, `paths.raw` и
`paths.metrics_collect`. Следующие стадии зависят от выходов предыдущих.

**Проверка числом.** При переключении версии вход очистки меняется с 1800 до
3000 строк, а её выход — с 1656 до 2763 строк. MD5 `clean.jsonl` для версий
различается, что проверяет пункт 4 `make check`.

## 3. Train и test были загрязнены общими примерами

**Проблема.** Построчное случайное разбиение не учитывало тематические группы.
Связанные вопросы могли оказаться одновременно в train и test.

**Как проявлялось.** Проверка контаминации находила совпадающие группы либо
одинаковые и почти одинаковые вопросы в разных сплитах.

**Исправление.** Разбиение выполняется целыми группами по нормализованному
полю `topic`. После split отдельная DVC-стадия `contamination` проверяет id,
текст, группы и near-duplicate пары и завершает пайплайн с ошибкой при любом
пересечении.

**Проверка числом.** Для `v2` получено 2211/276/276 строк в train/val/test.
Между train и test: 0 общих id, 0 общих текстов, 0 общих групп и 0 near-duplicate
пар.

## 4. Почти одинаковые вопросы переживали очистку

**Проблема.** Очистка удаляла только точные совпадения нормализованного текста.
Изменение пробелов, пунктуации или порядка частей позволяло копии сохраниться.

**Как проявлялось.** Два варианта одного вопроса оставались в `clean.jsonl`,
хотя точная дедупликация считала их разными.

**Исправление.** После точной дедупликации добавлен MinHash LSH по четырёхсловным
шинглам с порогом 0,85. Первый представитель группы остаётся, последующие
near-duplicate строки удаляются.

**Проверка числом.** На контрольном наборе из `make check` удаляется 1 точный и
1 почти одинаковый дубль. В согласованном снимке `v2` при этом пороге найдено
0 near-duplicate строк, то есть контроль не создаёт искусственных удалений.

## 5. Вырожденный датасет не останавливал пайплайн

**Проблема.** Метрики разнообразия вычислялись, но нарушение порогов не было
жёстким условием выполнения пайплайна.

**Как проявлялось.** Набор из 1200 однотипных строк с одной темой, одним
системным промптом и ответами одной длины принимался как корректный.

**Исправление.** Стадия `diversity` теперь завершается с ненулевым кодом и
перечисляет каждый нарушенный порог. Она включена в DVC-пайплайн между очисткой
и разбиением.

**Проверка числом.** Контрольный вырожденный набор нарушает 4 порога. Реальная
`v2` проходит гейт: 2763 примера, 5 системных промптов, 783 группы, доля
крупнейшей группы 5,07% при пределе 10% и p90/p10 длины ответа 10,59 при
минимуме 1,6.
