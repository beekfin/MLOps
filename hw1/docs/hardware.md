# ДЗ 1 — окружение и производительность машины

## Машина и профиль курса

Замер выполнен 8 сентября 2026 года на локальной машине.

| Характеристика | Значение |
| --- | --- |
| ОС | Arch Linux, ядро Linux 7.2.2-arch1-1, x86_64 |
| CPU | Intel Core i5-1145G7, 4 ядра / 8 логических потоков |
| Оперативная память | 16 064 976 КиБ, примерно 15,32 ГиБ (класс 16 ГБ) |
| Устройство инференса | CPU, выбран автоматически |
| GPU | Intel Iris Xe; CUDA и MPS недоступны в текущем окружении |
| Число вычислительных потоков PyTorch | 4 |
| Python | 3.12.13; версия 3.12 закреплена в `.python-version` |
| uv | 0.12.10 |
| Основные зависимости | torch 2.14.0, transformers 5.16.1, accelerate 1.14.0 |

По таблице из лекции 1, слайд 8 «Железо: почему ваш ноутбук не влияет
на оценку», машина соответствует профилю **x86 CPU-only, 8–16 ГБ RAM**.
Для этого профиля выбрана базовая модель курса с 0,6 млрд параметров.
Её идентификатор задан в `params.yaml`, в разделе `model.name`.

Базовая модель успешно загружается и генерирует ответ на CPU. Пиковая RSS
процесса составляет около 2,24 ГиБ при примерно 15,32 ГиБ системной RAM,
а измеренная скорость подходит для последовательных учебных запусков.
Поэтому переход на меньшую модель для ДЗ 1 не потребовался. Это проверка
инференса: требования будущего обучения к памяти здесь не измерялись.

Использован `bfloat16` из конфигурации курса. Сравнение с `float32`
в этом замере не проводилось; превосходство одного типа над другим
по скорости на данном CPU не утверждается.

## Условия и результаты замера

Команда запуска из каталога `hw1`:

```bash
uv sync --locked
make bench
```

Модель уже была скачана в локальный кэш. Загрузка включает вызов
`load_model()` с загрузкой токенизатора и весов, но не импорт Python-модулей
до входа в `main()`. Это не замер первичного скачивания весов из интернета.

Параметры запуска: `device: auto` (фактически CPU), `dtype: bfloat16`,
`temperature: 0`, `seed: 42`, `enable_thinking: false`, не более 200 новых
токенов. Промпт: «Объясни, что такое MLOps, в трёх предложениях.»
Выполнен один прогревочный и три измеряемых прогона в одном процессе.

| Метрика | Результат |
| --- | ---: |
| Время загрузки модели и токенизатора | 9,14 с |
| Медиана скорости генерации | 11,03 токена/с |
| Пиковая RSS за весь процесс | 2295,9 МиБ |
| Скорость первого измеряемого прогона | 11,03 токена/с |
| Скорость второго измеряемого прогона | 11,42 токена/с |
| Скорость третьего измеряемого прогона | 10,61 токена/с |

Для каждого прогона скорость равна фактическому числу новых токенов,
делённому на длительность вызова `generate()`. Этот вызов включает
подготовку промпта, токенизацию, генерацию и декодирование ответа.
Загрузка и прогрев исключены из этих длительностей. Лимит 200 токенов
не подставляется вместо фактического количества: ответ может закончиться раньше.

Пиковая RSS получена через `resource.getrusage(resource.RUSAGE_SELF).ru_maxrss`.
На Linux результат в КиБ переводится в МиБ делением на 1024. Это максимум
резидентной памяти всего процесса, включая библиотеки и модель, а не
снимок памяти в конце и не объём видеопамяти.

Сырые результаты записываются в `docs/bench.json`. Этот файл исключён
из Git, а результаты данного запуска сохранены в таблице выше.
На скорость влияют фоновые процессы и состояние ноутбука, поэтому
последующие запуски могут дать другие числа.

## Разбор четырёх дефектов

### 1. Имя модели было зашито в коде

В исходной заготовке идентификатор модели был строковой константой
в `src/model.py`, подписи вывода `src/generate.py` и отчёте `src/bench.py`.
Изменение `model.name` в конфиге не управляло загрузчиком; подпись и отчёт
тоже оставались привязаны к исходной модели.

Исправление: все три места получают значение из `params["model"]["name"]`.
Токенизатор и модель загружаются по одному имени из конфига. Общая логика
загрузки и генерации остаётся в `src/model.py` и переиспользуется обеими
точками входа. Самопроверка временно подменяет имя в YAML и проверяет
идентификатор действительно загруженной модели.

### 2. Зависимости не имели ограничений версий

В `pyproject.toml` были только названия библиотек. При новом подборе
зависимостей на другой машине или позднее могли выбираться другие версии,
что создавало риск изменения API и поведения без правок кода проекта.

Исправление: прямые зависимости закреплены через `==` на проверенных
версиях, а согласованный `uv.lock` фиксирует также транзитивные зависимости.
Оба файла входят в репозиторий. `.python-version` выбирает Python 3.12.
Команда `uv sync --locked` устанавливает окружение по существующему lock-файлу
и выявляет необходимость его обновления. В ходе подготовки выполнена
также проверка `uv sync --locked --offline` с локальным кэшем пакетов.

### 3. Скорость генерации включала загрузку и предыдущие прогоны

Исходный таймер запускался до `load_model()` и не перезапускался в цикле.
В знаменатель скорости попадали загрузка и предыдущие генерации, поэтому
скорость занижалась. Прогрева не было, а `load_time = 0.0` подменяла реальный
результат загрузки нулём.

Исправление: загрузка измеряется отдельно; затем выполняется число прогревов
из `bench.warmup_runs`. Перед каждым измеряемым вызовом `generate()`
таймер запускается заново. Из скоростей отдельных прогонов берётся медиана,
а реальное `load_time` сохраняется в отчёте. Пиковая RSS измеряется отдельно.
Новый запуск бенчмарка дал результаты, приведённые выше.

### 4. Генерация использовала случайный выбор без установки seed

В исходном конфиге стояла `temperature: 0.7`, включавшая сэмплинг.
Функция `set_seed()` существовала, но не вызывалась: само наличие
`seed: 42` в YAML не меняло состояния генераторов случайных чисел.
Поэтому одинаковый промпт мог давать разный текст при повторном запуске.

Исправление: задана `temperature: 0`; код выбирает `do_sample=False`
и не передаёт нулевую температуру в параметры сэмплинга.
Перед загрузкой модели в генерации и бенчмарке вызывается
`set_seed(params["generate"]["seed"])`, задающая seed для Python, NumPy
и PyTorch. Проверка повторяет генерацию и сравнивает вывод побайтово.
Такое сравнение относится к текущему окружению и устройству; идентичность
на произвольных версиях библиотек и разных устройствах не предполагается.

## Проверки перед сдачей

После исправлений `make bench` завершился успешно, а `make check`
прошёл все пять проверок: отсутствие имени модели в исходниках,
загрузка модели из подменённого конфига, одинаковый вывод двух генераций,
фиксация зависимостей и наличие разделённых замеров с прогревом.
Код замеров дополнительно проверен чтением: поиск ключевых слов
в пятой проверке сам по себе не доказывает корректность таймеров.

В репозитории сохранены `src/`, `tests/`, `docs/`, `data/`, `conf/`,
`Makefile`, `params.yaml`, `pyproject.toml`, `.python-version` и `uv.lock`.
Пустые каталоги `data/` и `conf/` сохраняются с помощью `.gitkeep`.
Окружение `.venv`, кэши Python и `.DS_Store` исключены из Git.
